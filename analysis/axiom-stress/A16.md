## Statement (as in spec)

Each pump cycle is one atomic transaction — ingest, normalise → match → size → abstract → route → certify, ±ΔINDX posted per provider — committing wholly or not at all. Grounded in A15 + T42.

## Derivation attempt

**Route 1 — dilemma (succeeds).** A15 already asserts its conserved quantity "permits balanced journaling" — well-defined only if some instant exists where intent in equals intent out. Read A15 as conservation at every observable state: a torn commit is a state where intent entered and did not exit — A15 violated, A16 follows. Read A15 weakly ("conserved eventually, in aggregate" — the reading used to defend A16's independence) and it stops supporting the double-entry consequence it already claims. Either A15 is strong and A16 is its granularity clause, or A15 is too weak for work already attributed to it. Both horns deny A16 independent content.

**Route 2 — attribution (partial).** Ambiguous per-provider attribution violates P6 (reward untethered from contribution) and A9 (a tear is exploitable internal information). So the *requirement* — unambiguous attribution — derives from P6 + A9 + A15. All-or-nothing commit at cycle granularity does not: it is one sufficient implementation among several (per-signal atomicity, compensating entries). Atomicity makes A15's accounting cheap, not possible.

**Route 3 — circularity (fatal).** §II requires axioms to be underivable from other axioms *or prior theorems*. A16's grounding is A15 + **T42** — a theorem. An axiom resting on a derived claim is a mislabelled corollary.

## Hidden assumptions

- A "cycle" exists: no primitive supplies time, tick, or batch granularity; cycle length is a free parameter.
- Ingestion→certification is bounded and terminating.
- Certification is a discrete, commit-triggerable event; T42 supplies no timing.
- Failures are fail-stop, not Byzantine; atomicity is assumed achievable, never shown.

## Load

Zero. No theorem cites A16 anywhere. T64 derives from A15 + T5 + T42, not A16 — the claim otherwise is unsupported. Stock-Flow Conservation derives from A15 + T42 + definitional accounting. Dropping A16 changes no derivation, only the axiom count.

## Recommendation

**Demote.** Fold the load-bearing content into A15; move the transaction property to the pump component spec as a conformance requirement.

A15 clause: "Conservation is enforced per discrete cycle: the aggregate is defined at cycle boundaries; no intermediate state is externally observable."

Conformance requirement: "The pump SHALL commit each cycle's postings atomically; no partial commit is externally visible."
