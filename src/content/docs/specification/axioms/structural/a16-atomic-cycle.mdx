**Status: demoted in v13.**

Atomic commit is an implementation property. It lives in the component specification as a conformance requirement on the matching and settlement components: *each cycle's postings SHALL commit atomically; no partial commit is externally visible.*

## Statement (v12)

Each processing cycle in the ★-center pump is one atomic transaction: signal ingested → normalise → match → size → abstract → route → certify → $\pm\Delta\text{INDX}$ posted per provider. The cycle commits as a single operation or not at all; partial commits are structurally impossible. Grounded in A15 (Intent Conservation) + T42 (External Validation).

## Why it was demoted

A16 was the only axiom in the set grounded on a theorem — T42 — which inverts the dependency order the axiom layer is supposed to hold. It was also cited by no theorem, so nothing downstream loses a premise when it is removed.

What it describes is a transactional property of the pump: real, required, and testable, but a specification a component must satisfy rather than a proposition the constitution assumes. Stated as a conformance requirement it becomes something an implementation can be checked against, which is what an implementation property should be.

Full reasoning: `analysis/axiom-stress/SYNTHESIS.md` in the repository.
